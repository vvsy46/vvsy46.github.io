## 1. Intro
![assets/img/wargame/kpwnote/run_sh.png](assets/img/wargame/kpwnote/run_sh.png)
우선 동적 분석을 위해 기존 run.sh에 `nowait` 옵션과 `-s`옵션을 추가했다.  
이후에는 **Description**처럼 
1. `nc localhost 8023`으로 쉘을 접속하고
2. 다른 터미널에서 `nc localhost 8088 < script`로 파일을 삽입한 후,
3. 접속한 쉘에서 `cat /dev/vport0p1 > /tmp/script`를 통해 파일을 가져왔다.
4. 일정 시간 후에 전송하던 터미널에서 `ctrl + c`를 입력해주면 된다. 

여기서 내 script는 `gcc -static -o shell shell.c`로 컴파일한 script이다.  
이후에는
```sh
$ gdb vmlinux
$ (gdb) target remote :1234
```
를 통해 디버깅이 가능하다.

## 2. KASLR Bypass
![assets/img/wargame/kpwnote/kaslr.png](assets/img/wargame/kpwnote/kaslr.png)  
우선 kaslr이 켜져 있다면 위처럼 주소를 읽을 수 없다.  
그 이유는 gdb는 vmlinux를 기준으로 켰기 때문인데, 그러므로 `nokaslr` 옵션을 붙여주면 된다.

![assets/img/wargame/kpwnote/leak_addr.png](assets/img/wargame/kpwnote/leak_addr.png)  
tmp배열의 이후 주소로 위처럼 커널 주소가 매핑되어 있는 영역이 있다.  
그런데 여기서 취약점을 이용하여 tlen의 값이 바뀐 것을 볼 수 있고, 이를 이용하여 kaslr을 구할 수 있다.

## 3. Exploit
### 3-1. SMEP X
현재 -cpu qemu64를 사용하는데, 여기에는 기본적으로 smep, smap이 없다.  
그러므로 leak한 주소를 바탕으로 commit_creds와 prepare_kernel_cred을 적절히 활용하여 root 권한을 얻을 수 있다.

#### 3-1-1. long 타입
처음 막힌 부분은 commit_creds(prepare_kernel_cred(0)) 삽입이다.  
우선 `my_lseek`의 주소를 overwrite하려고 진행했다.  
```c
extern loff_t my_lseek(struct file *file, loff_t offset, int whence);
static struct proc_ops my_fops = {
  .proc_lseek = my_lseek,
  .proc_read = my_read,
  .proc_write = my_write,
};
```
그런데 my_lseek의 자료형은 loff_t이고,  
이를 `void`나 다른 크기의 타입으로 overwrite를 진행하게 되면 `RAX`레지스터의 상태가 커널 복귀 시점에 오염되어 크래시가 발생할 수 있다.  

#### 3-1-2. 인자 3개
리눅스는 `RDI` -> `RSI` -> `RDX` -> `RCX` -> `R8` -> `R9` 레지스터를 사용한다.  
여기서 커널은 `proc_lseek`를 호출할 때 3개의 인자를 사용한다.  
그러므로 유저 함수에서 인자가 없거나 개수가 틀리다면 컴파일러가 **prologue/epilogue**를 생성할 때 `RSP`스택 포인터 오프셋 계산을 잘못하여 레지스터를 엉뚱하게 덮을 수 있다.

#### 3-1-3. __attribute__((noinline))
컴파일러는 코드 최적화 시에 호출 빈도가 적거나 단순한 함수를 `main`에 합치는 **인라인 최적화**를 수행한다.  
여기서 인라인화가 진행되면 유저가 만든 `shell` 함수가 없어지므로 인라인화를 막기 위해 삽입한다.

### 3-2. SMEP O
SMEP가 켜지면 커널(ring0)이 **유저 페이지의 코드를 실행할 수 없다.**  
그러므로 3-1의 ret2usr 방식(함수 포인터를 유저 함수 `shell`로 덮는 방식)은 실행 시점에 폴트가 발생하여 막힌다.  
따라서 유저 코드를 실행하는 대신, **커널 안에 이미 존재하는 가젯들을 이어붙이는 ROP**로 `commit_creds(prepare_kernel_cred(0))`를 구성해야 한다.  


#### 3-2-1. **mov rdi, rax ; ret** VS **push rax ; ret ; pop rdi**
`prepare_kernel_cred(0)`의 반환값(cred)은 `RAX`에 담긴다.  
이를 `commit_creds`의 인자로 넘기려면 `RAX -> RDI`로 옮겨야 한다.

처음에는 `push rax ; ret`과 `pop rdi ; ret` **두 가젯으로 나누어** 시도했다. 하지만 이 방식은 동작하지 않는다.  
각 가젯이 끝에 `ret`을 달고 있어서, `push rax` 직후의 `ret`이 방금 스택에 올린 cred 값을 **리턴 주소로 꺼내버리기** 때문이다.

즉 `push rax`와 `pop rdi` 사이에 `ret`이 끼면 안 되고, `push rax ; pop rdi ; ret`처럼 **한 가젯 안에 연속**이어야 한다.  
그런데 이 바이너리에는 이 단일 가젯도, 깔끔한 `mov rdi, rax ; ret`도 존재하지 않았기에 **`commit_creds(&init_cred)`** 를 사용했다.  

```c
rop[i++] = pop_rdi;
rop[i++] = init_cred;     // kernel_base + 0xc240e0
rop[i++] = commit_creds;  // kernel_base + 0x634e0
```

#### 3-2-2. Stack Pivot
`proc_lseek` 호출 시점의 레지스터를 확인하면 아래와 같다.
```
RDI = file
RSI = offset(lseek 인자)
RDX = whence
```
`RSI`는 `lseek`의 offset 인자라 제어 가능하다. 따라서 `mov rsp, rsi ; ret` 같은 피벗이 있으면 `RSP`를 내 체인으로 옮길 수 있다.
```
mov esp, esi ; mov rax, r12 ; pop rbx ; pop r12 ; pop rbp ; ret   ; @ base+0x263a7f
```
이를 위해 위의 가젯을 사용했는데, `mov esp, esi`는 **32비트**라 `RSP`가 낮은 주소로 세팅된다.  
그래서 ROP 체인을 낮은 유저 주소(`mmap(MAP_FIXED)`)에 배치하고, `lseek(fd, <체인 주소>, 0)`으로 `esi = 체인 주소`를 만들어 진행했다.  

#### 3-2-3. Double Fault - 체인 위치와 페이지 present
처음엔 체인을 `mmap` 한 페이지의 **맨 앞(0x10000000)** 에 두고 진행했더니 아래처럼 **double fault**가 났다.
```
RIP: proc_id_connector+0x4  (push rbx)
RSP: 0x10000000   CR2: 0x0ffffff8   double fault
```
원인은
1. **체인이 mmap 영역의 맨 밑에 있었다.** `commit_creds`는 uid 변경(1000 → 0) 시 `proc_id_connector`를 호출하는데, 이 커널 함수들이 스택을 쓰려고 `RSP` **아래로 push**한다. 또한, 체인이 맨 밑이면 그 아래는 매핑이 없어 언더플로우한다.  
→ 체인을 **큰 mmap의 중간**에 배치해 `위(체인 pop) / 아래(커널 push)` 여유를 준다.
2. **anonymous 페이지는 demand-paging**이라 유저가 안 건드린 페이지는 not-present다. 커널이 not-present 유저 페이지로 push하면 #PF가 나는데, 이때 `RSP`(=그 not-present 페이지) 위에 fault 프레임을 쌓을 수 없어 **#PF -> #DF**가 된다.  
→ mmap에 `MAP_POPULATE`를 주고 `memset`으로 **전 영역을 미리 present**로 만든다.

```c
void *m = mmap((void*)0x10000000, 0x100000, PROT_READ|PROT_WRITE,
               MAP_FIXED|MAP_PRIVATE|MAP_ANONYMOUS|MAP_POPULATE, -1, 0);
memset(m, 0, 0x100000);              // 전 페이지 present
uint64_t *rop = (uint64_t*)(0x10000000 + 0x40000);  // 중간에 배치
```

**demand-paging 상세**  
`mmap`을 호출해도 커널은 그 순간 물리 페이지를 주지 않는다. 대신 "이 주소 범위는 유효하다"는 **VMA(virtual memory area) 메타데이터만** 만들고, 페이지 테이블(PTE)은 비워둔다(not-present). 물리 페이지는 그 주소를 **처음 실제로 건드릴 때(first touch)** 할당된다.
```
process가 0x10040000에 write
  → PTE not-present → #PF
  → 커널 #PF 핸들러: VMA 안의 정당한 접근 확인
      → 물리 페이지 할당 + PTE 기록(present) → 명령 재실행 → 성공
```
그래서 체인을 쓴 `0x10040000` 근처만 present가 되고, 유저가 안 건드린 그 **아래 영역(0x10000000 ~ 0x1003ffff)은 여전히 not-present**로 남는다. ROP 실행 중 커널 함수가 `RSP` 아래로 push하면 이 not-present 페이지에 접근한다.

여기서 일반 #PF가 아니라 **#DF(double fault)** 가 되는 이유가 핵심이다. x86-64에서 커널모드 예외가 나면 CPU는 **현재 `RSP` 위에 예외 프레임(SS/RSP/RFLAGS/CS/RIP)을 push**해서 핸들러로 넘어가는데, `#PF`는 별도 IST 없이 현재 `RSP`를 그대로 쓴다. 그런데 지금은 `RSP` 자체가 not-present 페이지라, **폴트를 처리하려는 그 push조차 또 폴트**나서 #DF로 확정된다. 크래시 로그의 `CR2`(폴트 주소)가 `RSP` 바로 아래를 가리키는 것이 그 증거다.

또한 `MAP_POPULATE`만으로는 부족할 수 있다. anonymous private 매핑은 읽기용 **zero-page에 COW**로만 걸릴 수 있어서, 커널의 push(=write) 시점에 COW 브레이크 폴트가 날 여지가 있다. 그래서 `memset`으로 실제 write까지 해서 **writable 물리 페이지를 확정 present**로 만든다.

#### 3-2-4. 유저 복귀 (KPTI trampoline)
ROP로 `RSP`를 수정했으므로 정상 리턴 경로가 없다.  
그러므로 체인 끝에서 직접 유저로 복귀해야 한다.  
KPTI가 켜져 있으므로 `swapgs ; iretq`로는 CR3 전환이 안 되어 폴트가 나고,  
`swapgs_restore_regs_and_return_to_usermode + 22`(0x16, `mov rsp, rdi` 지점)를 경유해야 CR3 스왑까지 처리된다.
![assets/img/wargame/kpwnote/kpti.png](assets/img/wargame/kpwnote/kpti.png)

이 지점 이후 요구되는 스택 레이아웃은 다음과 같다.
```
[fake rax][fake rdi][RIP][CS][RFLAGS][RSP][SS]
```
그래서 익스플로잇 시작 시 `save_state`로 유저의 `CS/SS/RFLAGS/RSP`를 백업해두고, 체인 끝에 이 프레임을 쌓아 유저 함수(`shell`)로 iretq 복귀한다.  
이때 유저 착지점 `shell`은 3-1과 달리 `commit_creds`를 호출하지 않고 `system("/bin/sh")`만 수행한다.
```c
rop[i++] = kpti_trampoline;  // swapgs_restore_regs_and_return_to_usermode + 22
rop[i++] = 0;                // fake rax
rop[i++] = 0;                // fake rdi
rop[i++] = (uint64_t)shell;  // RIP (유저 착지점)
rop[i++] = user_cs;
rop[i++] = user_rflags;
rop[i++] = user_rsp;
rop[i++] = user_ss;
```
